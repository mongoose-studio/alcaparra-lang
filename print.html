AlcaparraLang

AlcaparraLang

AlcaparraLang es un lenguaje de scripting interpretado, propósito general, con fuerte foco en cálculos numéricos. Su caso de uso principal es la evaluación de fórmulas financieras y de nómina, aunque está diseñado para ser completamente independiente de ese dominio.

use std.math.{ round, min };

header {
    name: "liquidacion_standard";
    version: "1.0.0";

    const TASA_AFP      = 0.1157;
    const TOPE_IMPONIBLE = 81.0;
}

main {
    let bruto     = SUELDO_BASE ?? 0;
    let desc_afp  = round(bruto * TASA_AFP, 0);
    let liquido   = bruto - desc_afp;

    emit {
        bruto:    bruto,
        desc_afp: desc_afp,
        liquido:  liquido
    };
}

Características principales

  • Números exactos — usa Decimal de precisión arbitraria internamente. Sin errores de punto flotante en cálculos monetarios.
  • Mutabilidad explícita — let (inmutable), var (mutable), const (constante de script en header).
  • Inyección de contexto — las variables del entorno están disponibles directamente en el scope, sin declaración.
  • emit como salida — equivalente a return pero orientado a producir el resultado final del script.
  • Determinista — sin acceso a red, sistema de archivos ni estado global entre ejecuciones.
  • Embebible en Rust — el crate alcaparra expone Interpreter::run() para integración directa.

cargo install alcaparra-lang

caper run mi_script.caper --context '{"SUELDO_BASE": 850000}'

Estructura de un script

Un script .caper puede tener dos formas: con header y main, o directo (inline).

Con header y main

header {
    name:        "liquidacion_standard";
    version:     "1.2.0";
    description: "Liquidacion mensual con gratificacion garantizada";
    author:      "equipo-nomina";

    // Constantes: disponibles en main, nunca sobreescribibles por el contexto
    const TOPE_IMPONIBLE_UF          = 81.0;
    const TASA_CESANTIA_INDEFINIDO   = 0.006;
    const TASA_CESANTIA_PLAZO_FIJO   = 0.011;
    const TOPE_GRATIFICACION_MENSUAL = 4.75;
}

main {
    let bruto = SUELDO_BASE + (BONO_ASISTENCIA ?? 0);
    emit { resultado: bruto };
}

El bloque header es opcional pero recomendado para scripts nombrados y versionados.

Inline (sin header)

// El intérprete ejecuta el contenido directamente, como si fuera main
let sueldo_bruto = SUELDO_BASE + BONO_ASISTENCIA;
emit { sueldo_bruto: sueldo_bruto };

Útil para scripts cortos o evaluaciones directas desde API.

Constantes del header (const)

Las constantes declaradas en header tienen máxima precedencia:

  • No se pueden reasignar desde main
  • No pueden ser sobreescritas por el contexto inyectado
  • Están disponibles en todo el scope de main y en las funciones del script
header {
    name: "calculos_legales";
    version: "2.0.0";

    const UF_TOPE_IMPONIBLE = 81.0;
}

main {
    let tope = UF_TOPE_IMPONIBLE * UF;   // UF viene del contexto, la const es del script

    UF_TOPE_IMPONIBLE = 90.0;            // ERROR: ConstReassignment
}

Las constantes son ideales para valores legales que el operador no debe poder cambiar desde configuración externa — tasas y topes que emanan de la ley.

Comentarios

// Comentario de línea

/*
   Comentario de bloque.
   Puede ocupar múltiples líneas.
*/

let x = 10; // comentario al final de una línea

Punto y coma

Toda sentencia termina obligatoriamente en ;. Los bloques { } no llevan ; después de la llave de cierre, excepto cuando el bloque es parte de una expresión asignada.

// Sentencias simples — siempre ;
let x = 5;
var total = 0;
use std.math.round;
emit { valor: x };

// Bloques de control — sin ; después de }
if x > 0 {
    total = total + x;
}

foreach item in lista {
    total = total + item;
}

// Bloque como expresión asignada — el ; va al final
let categoria = match sueldo {
    n if n < 500_000 => "basico",
    _                => "alto"
};

let mensaje = if activo { "vigente" } else { "inactivo" };

Variables y tipos

Declaración

let nombre   = "Juan";    // inmutable — no se puede reasignar
var contador = 0;         // mutable — puede reasignarse

var total = 0.0;
total = total + 1000;     // OK

nombre = "Pedro";         // ERROR: ImmutableReassignment

Redeclarar una variable en el mismo scope también es un error:

let x = 1;
let x = 2;    // ERROR: VariableRedeclaration

El shadowing en scopes anidados sí está permitido:

let x = 1;
if condicion {
    let x = 99;   // OK — scope distinto
    emit x;       // 99
}
emit x;           // 1

Tipos de datos

TipoEjemploNotas
Número42, 3.14, -100, 1_000_000Siempre Decimal — sin float64
String"texto", 'texto'Comillas simples o dobles equivalentes
Booleanotrue, false

Números exactos

El tipo Decimal usa precisión arbitraria — nunca hay errores de punto flotante en cálculos monetarios:

let a = 0.1 + 0.2;   // 0.3 (exacto) — no 0.30000000000000004

Los guiones bajos en literales numéricos son ignorados (separador visual):

let tope = 1_000_000;   // equivalente a 1000000

Null coalescing (??)

El operador ?? retorna el lado derecho si el izquierdo es null:

let bono = BONO_ESPECIAL ?? 0;

// Encadenado
let config = A ?? B ?? C ?? "default";

Es la forma idiomática de dar valores por defecto a variables de contexto que podrían no estar presentes.

Inyección de contexto

Las variables externas se inyectan automáticamente en el scope base del script. No hay que declararlas:

// SUELDO_BASE, DIAS_TRABAJADOS, AFP_TASA, UF, UTM, etc.
// están disponibles directamente si el caller los inyectó

let bruto = SUELDO_BASE + (BONO_ASISTENCIA ?? 0);

Si una variable del contexto no fue inyectada, su valor es null. Usa ?? para el caso seguro.

Prioridad del scope:

const del header  >  let/var del script  >  contexto inyectado

Una const nunca puede ser sobreescrita por el contexto externo.

Operadores

Aritméticos

let suma     = a + b;
let resta    = a - b;
let producto = a * b;
let division = a / b;    // siempre Decimal, nunca división entera
let modulo   = a % b;    // resto de la división
let potencia = a ** b;   // a elevado a b

Los operadores aritméticos no convierten

Un string no es un número, aunque contenga dígitos. "100" * 2 es un error de tipo, no 200:

let s = "1850000";     // ojo: texto, no número

let mal  = s * 26;              // TYPE_ERROR
let bien = to_number(s) * 26;   // 48100000

Esto es a propósito, y es de las decisiones que más protegen un cálculo. Un contexto JSON trae números como string con facilidad —PostgreSQL serializa numeric así, y muchos lenguajes lo arrastran hasta el JSON—. Cuando la conversión era automática, "1850000" * 26 / 30 daba un resultado correcto y la primera suma lo concatenaba: el cálculo salía mal sin un solo error. Mejor que reviente en la primera operación.

Lo mismo vale para los booleanos: true no es 1.

Para convertir a propósito están to_number y to_string, que es justamente lo que hacen.

Comparación

a == b    // igual
a != b    // distinto
a > b
a < b
a >= b
a <= b

Lógicos

a and b    // AND lógico
a or b     // OR lógico
not a      // NOT lógico

String

let saludo = "Hola " + nombre;    // concatenación con +

Cualquier valor puede concatenarse con un string — se convierte automáticamente:

let msg = "Total: " + 850000;     // "Total: 850000"

+ es la excepción. Es a la vez suma y concatenación, así que cuando cualquiera de los dos lados es string el resultado es un string, no un error:

let a = 100 + "50";    // "10050", no 150

Es lo que permite escribir mensajes de error sin convertir a mano, pero significa que un acumulador numérico que se sume con un string del contexto se vuelve texto en silencio. Si el valor puede venir como string, pásalo por to_number antes de acumularlo.

Acceso a colecciones

arr[0]         // acceso por índice base 0
arr[-1]        // último elemento (índice negativo)
arr[1..3]      // rango: elementos 1 y 2 (3 excluido)

obj.clave      // acceso a objeto por nombre de campo
obj["clave"]   // acceso por string dinámico (equivalente)

Null coalescing

valor ?? fallback    // retorna fallback si valor es null

Control de flujo

if / else if / else

if sueldo_base > 1_000_000 {
    var categoria = "alto";
} else if sueldo_base > 500_000 {
    var categoria = "medio";
} else {
    var categoria = "basico";
}

if como expresión

let jornada = if horas_contrato >= 45 { "completa" } else { "parcial" };

match

// Sobre valor exacto
let desc = match TIPO_CONTRATO {
    "indefinido" => "Contrato a Plazo Indefinido",
    "plazo_fijo" => "Contrato a Plazo Fijo",
    "honorarios" => "Boleta de Honorarios",
    _            => "Tipo no reconocido"
};

match con guards

let tramo = match sueldo_bruto {
    n if n <= 800_000   => 0.0,
    n if n <= 1_700_000 => 0.04,
    n if n <= 2_500_000 => 0.08,
    n if n <= 3_300_000 => 0.135,
    _                   => 0.23
};

Los patrones se evalúan en orden. El primero que coincide gana. _ es el caso por defecto.

while

var i    = 0;
var suma = 0;

while (i < count(haberes)) {
    suma = suma + haberes[i];
    i = i + 1;
}

foreach

// Iterar sobre un array
foreach haber in haberes {
    total = total + haber;
}

// Con índice numérico
foreach i, haber in haberes {
    // i: 0, 1, 2...  |  haber: el valor
}

// Iterar sobre un objeto
let tasas = { "habitat": 0.1157, "cuprum": 0.1044 };

foreach codigo, tasa in tasas {
    // codigo: "habitat", "cuprum"...  |  tasa: el valor numérico
}

break y continue

Disponibles en while y foreach:

foreach item in lista {
    if item < 0 { continue; }    // salta al siguiente
    if item > 1000 { break; }    // termina el loop
    total = total + item;
}

Funciones y closures

Declaración

fn calcular_gratificacion(sueldo_base, meses_trabajados) {
    let base_anual   = sueldo_base * 12;
    let proporcional = base_anual * 0.25 * meses_trabajados / 12;
    let tope         = TOPE_GRATIFICACION_MENSUAL * UTM / 12;

    emit min(proporcional, tope);
}

emit dentro de una función es el equivalente a return. Si no hay emit, la función retorna null.

Llamada

let grat = calcular_gratificacion(SUELDO_BASE, MESES_TRABAJADOS);

Recursión

fn factorial(n) {
    if n <= 1 {
        emit 1;
    } else {
        emit n * factorial(n - 1);
    }
}

let resultado = factorial(5);   // 120

Closures (funciones anónimas)

// Closure de expresión única
let calcular_afp = |sueldo| => sueldo * AFP_TASA;

// Closure con cuerpo
let aplicar_descuento = |monto, porcentaje| => {
    let descuento = monto * porcentaje;
    emit monto - descuento;
};

// Como argumento directo (HOF)
let montos_netos = map(haberes, |h| => h * 0.9);

let mayores_a_cien = filter(valores, |v| => v > 100);

let total = reduce(haberes, |acc, h| => acc + h, 0);

emit como return de función

A diferencia de otros lenguajes, emit no solo produce la salida del script — también funciona como return dentro de funciones:

fn clasificar(n) {
    if n < 0     { emit "negativo"; }
    if n == 0    { emit "cero"; }
    emit "positivo";
}

let clase = clasificar(-5);   // "negativo"

El primer emit ejecutado dentro de la función termina su ejecución.

Arrays y objetos

Arrays

let haberes = [SUELDO_BASE, BONO_ASISTENCIA, HORAS_EXTRA_MONTO];

// Tipos mixtos (permitido)
let mixto = [1, "dos", true, null, 3.14];

let tramos = [

let ultimo   = haberes[-1];      // índice negativo: desde el final

Spread

let base      = [100, 200];
let extendido = [...base, 300];   // [100, 200, 300]

Objetos

let empleado = {
    nombre:  NOMBRE,
    rut:     RUT,
    jornada: HORAS_CONTRATO,

Acceso

let nombre = empleado.nombre;      // dot notation
let rut    = empleado["rut"];      // equivalente con string dinámico

Objetos anidados

let contrato = {
    empleado: empleado,
    tipo:     TIPO_CONTRATO,
    inicio:   FECHA_INICIO

let nombre_en_contrato = contrato.empleado.nombre;

Spread en objeto

let base_obj  = { nombre: "Juan", activo: true };
let extendido = { ...base_obj, cargo: "Analista" };
// { nombre: "Juan", activo: true, cargo: "Analista" }
// Si hay clave duplicada, la más a la derecha prevalece.

Mutabilidad

Los objetos let son completamente inmutables — ningún campo puede modificarse:

let empleado = { nombre: "Juan" };
empleado.nombre = "Pedro";    // ERROR: ImmutableReassignment

Los objetos var permiten mutación de campos individuales:

var resultado = {};
resultado.sueldo_bruto     = sum(haberes);
resultado.total_descuentos = sum(descuentos);
resultado.liquido          = resultado.sueldo_bruto - resultado.total_descuentos;

Manejo de errores

try / catch

try/catch captura cualquier error — tanto los lanzados con throw como los errores internos del runtime:

// Como expresión con valor
let tasa = try {
    tasas_afp[AFP_CODIGO];
} catch e {
    0.1157    // valor por defecto si la clave no existe
};            // ; al final porque es una expresión asignada

// Como sentencia
try {
    let resultado = operacion_riesgosa();
    emit resultado;
} catch e {
    emit { error: true, mensaje: e.message };
}

El objeto e siempre tiene dos campos:

CampoTipoDescripción
e.codestringCódigo del error. Para throw con objeto: el code del usuario. Para errores internos: el código de runtime ("DIVISION_BY_ZERO", etc.).
e.messagestringMensaje legible.

throw

throw termina la ejecución del bloque actual lanzando una excepción:

// Con mensaje simple
throw "El sueldo base no puede ser cero";

// Con objeto estructurado (recomendado)
throw { code: "SUELDO_INVALIDO", message: "El sueldo base debe ser positivo" };

throw en funciones

fn validar_sueldo(base) {
    if base <= 0 {
        throw { code: "VALIDACION", message: "sueldo debe ser positivo" };
    }
    emit base;
}

let r = try {
    emit validar_sueldo(-1);
} catch e {
    emit e.code + ": " + e.message;   // "VALIDACION: sueldo debe ser positivo"
};

Excepción no capturada

Si un throw no está dentro de ningún try/catch, el script termina con error:

{
    "status": "error",
    "error": {
        "type":    "USER_THROW",
        "code":    "SUELDO_INVALIDO",
        "message": "El sueldo base debe ser positivo",
        "line":    12
    }
}

Para errores internos del runtime (división por cero, tipo incorrecto, etc.):

{
    "status": "error",
    "error": {
        "type":    "DIVISION_BY_ZERO",
        "message": "Division by zero at line 8"
    }
}

Imports y proyectos

Stdlib

use std.math;                              // importa todo el módulo
use std.arrays.{ sum, avg, filter };       // funciones específicas
use std.strings.upper;                     // una sola función
use std.dates;

Las funciones importadas están disponibles directamente por nombre en el resto del script.

Librerías propias (multi-archivo)

Los scripts .caper pueden importar funciones de otros archivos .caper. El archivo importado opera en library mode: solo se exportan las funciones declaradas con fn. Las sentencias emit en librerías son ignoradas.

// Importar funciones específicas
use formulas.gratificacion.{ calcular, tope };
use lib.validaciones.{ validar_positivo, validar_rango };

// Usar con normalidad
let grat = calcular(SUELDO_BASE, DIAS_TRABAJADOS);

Resolución de rutas: formulas.gratificacion → formulas/gratificacion.caper relativo al directorio base del script principal.

Path aliases

Define aliases en .capercfg para rutas largas o compartidas (similar a paths en tsconfig.json):

{
    "paths": {
        "@lib":      "./lib",
        "@formulas": "/opt/formulas-nacion"
    }
}

use @lib.validaciones.{ validar_positivo };
use @formulas.afp.{ calcular_descuento };

Paquetes de terceros (vendors/)

Los paquetes instalados con caper install se resuelven desde vendors/:

use @mongoose/nomina-cl.afp.{ calcular_descuento };
use mongoose/utils.fechas.{ es_feriado };

# Instalar un paquete local o git
caper install /ruta/local/mi-paquete
caper install git+https://github.com/org/paquete --tag v1.0.0

Proyecto — .capercfg

Un directorio con .capercfg es un proyecto. Permite correr caper run sin especificar script:

{
    "name":        "liquidacion-mensual",
    "version":     "1.0.0",
    "description": "Fórmulas de liquidación estándar",
    "author":      "Marcel Rojas",
    "entry":       "main.caper",
    "context": {
        "UF":  36000,
        "UTM": 65000
    },
    "paths": {
        "@lib":      "./lib",

CampoDefaultDescripción

context{}Variables de contexto base

Precedencia de contexto: --context CLI > context en .capercfg.

Búsqueda del config: el CLI sube por el árbol de directorios hasta encontrar .capercfg. Si no existe, termina con error.

Comportamiento de imports

  • Cache: un archivo importado por múltiples scripts en la misma ejecución se carga una sola vez.
  • Circular imports: A → B → A lanza CIRCULAR_IMPORT inmediatamente.
  • Library mode: el header de un archivo importado es privado para ese archivo. Solo sus fn son exportadas.

Ejemplos

use std.math.{ round, min, abs, ceil, floor };

let desc_afp  = round(850000 * 0.1157, 0);   // 98345
let desc_tope = min(desc_afp, 100000);        // 98345

let diferencia = abs(-5000);                  // 5000
let pagos       = ceil(1500 / 400);           // 4 (cuotas)
let parte_entera = floor(3.99);              // 3

Redondeo — lo más importante del módulo

round(1234.567, 2)    // 1234.57
round(1234.567, 0)    // 1235
round(1234.567, -2)   // 1200   — los decimales negativos redondean a decenas, centenas y así

Hay dos estrategias y la diferencia importa. round redondea medio al par: el 0,5 va al entero par más cercano.

round(0.5, 0)   // 0     ← no 1
round(1.5, 0)   // 2
round(2.5, 0)   // 2     ← no 3
round(3.5, 0)   // 4

Es la estrategia correcta para estadística y para promediar: no sesga hacia arriba. Pero no es la que usa la contabilidad en Chile, que redondea medio hacia arriba. Para eso está round_half_up:

round_half_up(0.5, 0)   // 1
round_half_up(2.5, 0)   // 3
round_half_up(-2.5, 0)  // -3    — se aleja del cero

Para plata, round_half_up. Con un imponible de $1.005.000 la AFP sale 115.474,5: round da 115.474 y round_half_up da 115.475. Un peso de diferencia en una liquidación es un reclamo.

Logaritmos — la excepción a la exactitud

Todo el resto del módulo trabaja en decimal exacto. log, log10 y exp no: no existe un logaritmo exacto en decimal, así que devuelven una aproximación. Siguen siendo deterministas —misma entrada, misma salida, siempre— pero no se usan para plata.

log(8, 2)      // 3 (aprox)
log10(100)     // 2 (aprox)
exp(1)         // 2.7182818... (aprox)

clamp

clamp(5, 1, 10)    // 5
clamp(50, 1, 10)   // 10
clamp(0, 1, 10)    // 1

Un rango invertido (min > max) es un error, no un resultado silencioso.

substr y substring no son lo mismo

Los dos nombres existen y cada uno tiene la semántica que se le conoce por convención. El tercer argumento es lo que cambia: substr recibe un largo, substring una posición final.

substr("abcde", 1, 3)      // "bcd"  — tres caracteres desde la posición 1
substring("abcde", 1, 3)   // "bc"   — desde la posición 1 hasta la 3, excluida

Las posiciones se cuentan en caracteres, no en bytes

Importa en español, donde las tildes y la ñ ocupan más de un byte.

index_of("mañana", "n")    // 4   — no 5
char_at("mañana", 2)       // "ñ"

Nada muta

set y delete devuelven una copia y dejan el original intacto, igual que push sobre arreglos. En un lenguaje determinista conviene que nada cambie a espaldas de quien llama.

use std.objects.{ set, delete, keys };

let base = { a: 1, b: 2 };
let con_c = set(base, "c", 3);      // { a: 1, b: 2, c: 3 }
let sin_a = delete(base, "a");      // { b: 2 }
keys(base);                          // ["a", "b"]  — intacto

Borrar una clave que no existe no es un error: devuelve la copia igual. Y el orden de las demás claves se conserva.

entries y from_entries son ida y vuelta

use std.objects.{ entries, from_entries };

let o = { a: 1, b: 2 };

El contexto no se convierte solo

Los valores que entran por el contexto llegan con el tipo que traen. Un número mandado como texto queda como texto, y compararlo con un número es un error de tipo, no una coerción silenciosa:

// contexto: { "SUELDO": "850000" }

number(SUELDO) > 500000   // true

Es a propósito: en un motor de cálculo, adivinar tipos es peor que fallar temprano. Si quien arma el contexto manda números como texto, conviene convertirlos ahí y no en cada script.

Caso real: validar y limpiar RUT

use std.regex.{ regex_match, regex_replace_all };

fn validar_rut(rut) {
    // Acepta formatos: "12345678-9", "12.345.678-9", "12345678K"
    let rut_limpio = regex_replace_all(rut, "[^0-9kK-]", "");

    if not regex_match(rut_limpio, "\\d{1,8}-?[\\dkK]") {
        throw { code: "RUT_INVALIDO", message: "Formato de RUT incorrecto: " + rut };
    }
    emit rut_limpio;
}

Ejemplo completo — Liquidación Standard

Script de liquidación mensual básica con gratificación garantizada. Cubre el flujo completo de haberes, descuentos previsionales y cálculo de sueldo líquido.

Contexto requerido

VariableTipoDescripción
SUELDO_BASEnúmeroSueldo base mensual
DIAS_TRABAJADOSnúmeroDías trabajados en el mes
DIAS_HABILESnúmeroDías hábiles totales del mes
HORAS_EXTRA_MONTOnúmeroMonto calculado de horas extra
AFP_TASAnúmeroTasa AFP del trabajador (ej. 0.1157)
FONASA_TASAnúmeroTasa de salud (ej. 0.07)
FONASA_MINIMOnúmeroPiso mínimo de cotización salud
TIPO_GRATIFICACIONstring"garantizada" u otro
MESES_ACUMULADOSnúmeroMeses trabajados en el año (para gratificación)
TIPO_CONTRATOstring"indefinido", "plazo_fijo" u otro
UFnúmeroValor UF del período
UTMnúmeroValor UTM del período

Script

// liquidacion_standard.caper
// Liquidación mensual con gratificación garantizada.

use std.math.{ max, min, round };
use std.arrays.{ sum };

header {
    name:    "liquidacion_standard";
    version: "1.0.0";

    // Topes y tasas legales — no sobreescribibles por configuración de tenant
    const TOPE_IMPONIBLE_UF          = 81.0;
    const TOPE_GRATIFICACION_MENSUAL = 4.75;
    const TASA_CESANTIA_INDEFINIDO   = 0.006;
    const TASA_CESANTIA_PLAZO_FIJO   = 0.011;
}

main {
    // -- Validación de contexto mínimo --
    let sueldo_base = SUELDO_BASE ?? 0;
    if sueldo_base <= 0 {
        emit { error: true, codigo: "SUELDO_BASE_INVALIDO" };
    }

    // -- Tope imponible --
    let tope_pesos     = TOPE_IMPONIBLE_UF * UF;
    let base_imponible = min(sueldo_base, tope_pesos);

    // -- Haberes --
    let factor_asistencia = DIAS_TRABAJADOS / DIAS_HABILES;
    let bono_asistencia   = round(sueldo_base * factor_asistencia * 0.05, 0);

    let gratificacion = if TIPO_GRATIFICACION == "garantizada" {
        let proporcional = sueldo_base * 0.25 * MESES_ACUMULADOS / 12;
        round(min(proporcional, TOPE_GRATIFICACION_MENSUAL * UTM / 12), 0)
    } else {
        0
    };

    let horas_extra  = HORAS_EXTRA_MONTO ?? 0;
    let haberes      = [sueldo_base, bono_asistencia, gratificacion, horas_extra];
    let sueldo_bruto = sum(haberes);

    // -- Descuentos previsionales --
    let desc_afp   = round(base_imponible * AFP_TASA, 0);
    let desc_salud = round(max(base_imponible * FONASA_TASA, FONASA_MINIMO), 0);

    let desc_cesantia = match TIPO_CONTRATO {
        "indefinido" => round(base_imponible * TASA_CESANTIA_INDEFINIDO, 0),
        "plazo_fijo" => round(base_imponible * TASA_CESANTIA_PLAZO_FIJO, 0),
        _            => 0
    };

    let descuentos       = [desc_afp, desc_salud, desc_cesantia];
    let total_descuentos = sum(descuentos);

    // -- Resultado --
    emit {
        sueldo_bruto:     sueldo_bruto,
        total_descuentos: total_descuentos,
        sueldo_liquido:   sueldo_bruto - total_descuentos,
        detalle: {
            haberes: {
                sueldo_base:     sueldo_base,
                bono_asistencia: bono_asistencia,
                gratificacion:   gratificacion,
                horas_extra:     horas_extra
            },
            descuentos: {
                afp:      desc_afp,
                salud:    desc_salud,
                cesantia: desc_cesantia
            }
        }
    };
}
